# Coastal Simple Tools — CLAUDE.md

## Project Overview
A statically exported Next.js 15 site that hosts a growing collection of simple, focused tools built by Coastal Simple. The landing page lists tools as cards; each tool lives under its own route (e.g. `/wordcloud`). Deployed to GitHub Pages at `https://coastal-simple.github.io/tools/` via GitHub Actions on every push to `main`.

**Current tools:**
- **Word Cloud Generator** (`/wordcloud`) — multi-step flow: Import text → Filter stop words → Generate & export PNG/JPG/SVG

## Project Structure
```
src/
  app/
    layout.tsx          # Root layout — imports globals.css
    page.tsx            # Landing page — tool cards grid
    globals.css         # All shared styles (no CSS modules)
    wordcloud/
      layout.tsx        # Word Cloud shell with sticky header + logo
      page.tsx          # Word Cloud landing/splash
      import/page.tsx   # Step 1 — paste or upload text
      filter/page.tsx   # Step 2 — review and remove stop words
      generate/page.tsx # Step 3 — tune, preview, and export
  lib/
    wordcloud/
      types.ts          # Shared TypeScript types
      storage.ts        # sessionStorage persistence across steps
      textProcessor.ts  # Tokenisation and frequency counting
      stopWords.ts      # Default stop-word list
      colorUtils.ts     # Color palette helpers
public/
  logo.png             # Coastal Simple logo (32 × 32)
  wordcloud.png        # Tool preview image for the landing card
.github/workflows/deploy.yml  # CI: build → upload artifact → deploy Pages
```

## Build & Development
```bash
npm run dev      # local dev server (basePath is empty, so images load at /logo.png)
npm run build    # production static export → out/  (basePath becomes /tools)
```
The GitHub Actions workflow runs `npm ci && npm run build` and deploys `out/` to GitHub Pages. Do not commit the `out/` directory — it is generated by CI.

## Deployment Architecture
- `next.config.ts` sets `output: "export"` and `basePath: "/tools"` in production (`NODE_ENV === "production"`).
- `NEXT_PUBLIC_BASE_PATH` is exposed as a build-time env var and must be prepended to every image `src` that references `/public/` assets (e.g. `src={`${process.env.NEXT_PUBLIC_BASE_PATH}/logo.png`}`). This is required because `next/image` with `unoptimized: true` does not apply `basePath` to image srcs in static export HTML.
- JS/CSS assets get the basePath prefix automatically.

### Typography
- Font: `'Aptos', Arial, sans-serif`; base 15px / line-height 1.55
- `h1` — 2rem, weight 700, tracking -0.5px
- `h2` — 1.4rem, weight 600, tracking -0.3px
- `h3` — 1.1rem, weight 600

### Visual Design Language
- Light teal background (`#B9EDED`) with translucent white cards — airy, clean feel
- Sticky frosted-glass header (60px tall, `backdrop-filter: blur(8px)`)
- All interactive elements use the teal accent; no dark mode
- Cards lift on hover (`translateY(-3px)` + larger shadow)
- Buttons: `.btn-primary` (solid teal), `.btn-secondary` (outline teal), `.btn-ghost` (grey), `.btn-danger` (red); sizes `.btn-sm`, `.btn-lg`, `.btn-icon`
- Form controls: white background, 1.5px border, focus ring uses `--accent-light`
- Tags/chips: teal tint background with teal border

### Key CSS Classes

- Layout: `.page-shell`, `.page-header`, `.page-main`
- Cards: `.card` (translucent), `.card-solid` (opaque), `.card-p` (24px padding), `.card-p-sm` (16px)

- Tables: `.word-table`, `.word-count-bar`
- Utilities: `.flash-highlight`, `.transparent-bg` (checkerboard for transparent canvas preview)

## Adding a New Tool
1. Create `src/app/{toolname}/page.tsx` (and `layout.tsx` if it needs its own header).
2. Add a card to the landing page in `src/app/page.tsx`.
3. Add a preview image to `public/{toolname}.png`.
4. Keep all tool-specific logic and state inside the tool's folder.
5. Use `sessionStorage` (see `src/lib/wordcloud/storage.ts` for the pattern) to pass state between steps if the tool is multi-step.
6. Any image `src` pointing to `/public/` assets must be prefixed with `process.env.NEXT_PUBLIC_BASE_PATH`.

## Coding Conventions
- TypeScript throughout; 2-space indentation
- `camelCase` variables/functions, `PascalCase` components, lowercase route folders
- No CSS modules — all styles go in `globals.css` using the existing token system
- Keep tool logic isolated in `src/lib/{toolname}/`
- Do not add server-side rendering or API routes — the build must remain fully static
